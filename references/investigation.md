# 缺圖及接口變動追查

## 先區分缺圖位置

比較三份數據：搜尋摘要、圖集回應、實際下載結果。圖集已有 URL 而下載失敗，應處理傳輸或格式；圖集根本未列出，應調查其他素材來源。不要用重試下載解決收集階段缺圖。

先確認劇本 ID、發行方及版本。將關鍵詞搜尋找到的其他作品、文章或不同版本保存為「相關待確認」，經核對後才併入所選作品。票根、NPC、玩家角色、先行版與封面分別註記；官方圖的張數不能直接當角色人數。

## 追實際作品頁

1. 開啟指定作品的公開頁面，例如 `https://qiandao.com/spu?id=<作品ID>`，取得實際載入的 script URLs 與相關圖片請求。
2. 只沿該頁面明確引用的路由 chunk、圖片元件與 API wrapper 追查。共享 SDK 存在某個方法，不足以證明作品頁呼叫它；舊 PC 商城 bundle 也不一定是一般 `/spu` 頁面的來源。
3. 在既有瀏覽器開發者工具觀察公開請求，保留去除憑證的 URL、方法、參數、成功狀態、schema、分組與分頁欄位。避免匯出整份包含私人內容的瀏覽器紀錄。
4. 必要時使用環境已有的 REA 對公開 JavaScript 做靜態分析或解析已去除敏感資料的 HAR。按該版本工具說明選擇命令；不要為此自動改動全域 MCP、瀏覽器或系統設定。
5. 記錄公開檔案 URL、抓取時間、SHA-256、caller 位置及資料路徑；以正常匿名請求成功回應驗證推論，再加入通用程式。

本方法的既有追查確曾使用 REA 分析公開程式，最後的 HTTP 200 由獨立匿名客戶端驗證。REA 的靜態結果含 `partial`／`unknown`，不能聲稱完整恢復全部動態呼叫；503 HAR 或失敗的瀏覽器錄製也不是成功圖集證據。

若無法透過現有瀏覽器取得頁面，可直接請使用者提供作品分享連結或已公開的素材文章；不要讀取私人 Cookie 或瀏覽器設定檔來補足缺失。

## 補充來源

若公開作品頁明確引用 miniapp 設定或其他官方資源，可沿實際設定 URL 追查圖片欄位。《兇手與戀人》的歷史追查曾找到公開的 `dramaxiongshouyulianren/default.json` 與 `cast-selector` 題庫，但這是該作品的獨立素材來源，不能假設每本劇本都有相同 slug 或設定結構。

其他公開平台的資料應保留作者／發行方、原文頁、原圖 URL、版本及內容核對狀態。隨附下載程式僅支援已核對的千島 CDN；其他來源須使用代理現有下載工具並採用相同的像素、雜湊及來源紀錄原則。不要猜測 CDN 檔名或遍歷不存在的網址。

只有圖片、快取或回應的可靠證據才能補入素材清單；無法定位時明確記錄缺項。已收集目前來源全部分組，仍不能保證涵蓋全網歷史版本。
